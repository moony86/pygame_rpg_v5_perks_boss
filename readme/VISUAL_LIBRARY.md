# Visual Library — الفن ومنطق اللعبة منفصلان

## ما الذي يغطيه النظام؟

- ربط مستقل لكل نوع من أنواع EnemyType الحالية (15 نوعاً)، مع 8 عائلات فنية.
  التنويعات السريعة والثقيلة لها ربط مستقل للحجم والتلوين ويمكن استبدال صورتها.
- في الكود الحالي زعيم واحد بثلاث مراحل، وليس ثلاثة زعماء بذكاء مختلف.
  لكل مرحلة ربط بصري مستقل دون تغيير منطق هجماتها.
- صور منفصلة لطلقات اللاعب والعدو، وتنويعات الحرجة/المتفجرة/المساعد/الشوريكن/
  الملاحقة والسقوط. دقة التصادم تظل بنصف القطر الأصلي، لا بحجم الصورة.
- خمس درجات XP برسوم كريستال قابلة للتبديل والتلوين، دون تغيير قيمة الخبرة.
- الذهب القديم مربوط بالمكتبة أيضاً، مع إعادة استخدام ورقة coin.png ذات 6 إطارات.
- صور إصابة وانفجار وحلقة صدمة وأثر قطع، مع شفافية وعمر قابلين للتعديل.
- صورة مستقلة لكل كرت من الكروت الـ21. الصور السابقة الخمس محفوظة دون حذف.
- إطار كرت وصورة وعنوان ووصف وألوان build/legendary ومسافات كطبقات منفصلة.

## الاستخدام من المحرر

احفظ أي عمل مفتوح ثم حدّث الصفحة المحلية. افتح «العناصر والأصول».
التصنيفات تشمل الأعداء، الزعيم ومراحله، الطلقات، XP، المؤثرات، الكروت وإطارها.
البحث يقبل اسم العنصر أو معرّفه. لا تحتاج إلى تعديل ملف Python لتبديل الرسم.

يمكن تعديل PNG، الحجم، اللون، الشفافية، عدد الإطارات، الأعمدة والصفوف وFPS.
للأنيميشن اختر ملف sprite sheet منظماً، وcell=-1، ثم أدخل أبعاده وعدد الإطارات.
الأصول الجديدة الحالية صور ثابتة؛ دعم الأوراق المتحركة لا يعني أن دورة مشي
كاملة مرسومة لكل عدو قد أُنتجت بالفعل. النبض والفلاش والانتقالات تُطبق وقت العرض.

في الكروت يمكن اختيار كل صورة منفردة أو `card_style` للإطار والتخطيط:
حجم الصورة، موضع العنوان والوصف، تباعد السطور وألوان النص والفئات والندرة.
الحقول البصرية لا تغيّر وصف الكرت أو أثره أو ندرة ظهوره.

الحفظ يكتب الربط إلى `assets/data/game_objects.json`. تُدمج التعريفات الجديدة
من `assets/data/visual_defaults.json` دون استبدال قيم الشخصية أو السلاح التي
سبق تعديلها. ابدأ جولة جديدة لقراءة التغييرات. تغيير المرحلة ليس مطلوباً.

## ضمان وضوح اللعب

صورة العدو لا تغيّر health/speed/hitbox/AI. حجم الرصاصة البصري لا يغيّر radius.
مؤشرات التحذير وحدود الخطر الهندسية تبقى دقيقة في الكود؛ الصورة ليست بديلاً
عن حساب منطقة الضرر. هذا مقصود حتى لا يصبح تغيير الفن تغييراً في قواعد اللعب.
أرقام الضرر وشرائط الصحة والنصوص تبقى نصوصاً قابلة للقراءة، وليست صوراً ثابتة.

التلوين غير الأبيض يستخدم أعلى قناة RGB كقيمة إضاءة ثم يلوّن الرسم للمحافظة
على وضوح اللمعات المشبعة، بدلاً من تعتيم الأحمر والبنفسجي إلى بني باهت.
الأبيض يحافظ على الألوان الأصلية. الشفافية محفوظة، والتحميل مصغّر ومخزن مؤقتاً.
يمكن استبدال جميع PNG من قائمة الملفات الموجودة داخل assets.

## الملفات

- `assets/visuals/`: العائلات الثماني والمؤثرات والطلقات والكريستال وإطار الكرت.
- `assets/cards/art_v2/`: صور الكروت الـ21.
- `assets/data/visual_defaults.json`: روابط الفن الافتراضية دون قواعد القتال.
- `systems/object_catalog.py`: التحقق والتحميل والأنيميشن والتلوين.
- `tools/level_editor_web/visual_inspector.js`: البحث والتصنيفات والمعاينة الحية.
- `tools/check_visual_library.py`: تغطية الربط، الفصل عن التصادم، الأنيميشن والرسم.

هذه نقلة فنية وأداة تأليف، وليست تصريحاً بأن توازن جميع الجولات أو الأداء على
كل الأجهزة أصبح جاهزاً للنشر. لم يُعد بناء EXE ضمن هذه الخطوة.

## التحقق المنفذ

تغطية آلية لكل أنواع الأعداء والكروت، واختبار رسمهم دون تغيير صحتهم وتصادمهم،
وانتقاء إطارات الأنيميشن، وانتهاء المؤثرات، ورفض قيم الألوان/الأوراق/التخطيط
الخاطئة. جرى فحص جميع تنويعات الكروت العادية والأسطورية.
المراجعة البصرية شملت صور المعركة والزعيم والكروت، وتجربة حركة وإطلاق وDash
واختيار كرت بالكيبورد، ومحرر بعروض 1440 و390 و360 بكسل. نسخة المتصفح للاختبار
الداخلي فقط، وليست منصة إصدار جديدة. صور الأدلة في debug_screenshots/visual_library.

تحتوي المكتبة حالياً على 64 ربطاً قابلاً للتحرير، منها 21 صورة كرت، و15 نوع
عدو، وربطان إضافيان لمرحلتي الزعيم الثانية والثالثة، مع العناصر السابقة.
صور المؤثرات لا تستبدل مؤشرات الخطر الهندسية أو النصوص الضرورية للقراءة.
ملف `readme/visual-generation-prompts.json` يسجل كل نصوص توليد الصور النهائية
وطريقة التوليد المدمجة. لم تُستخدم حزمة فن تجارية أو تنزيلات طرف ثالث جديدة.
